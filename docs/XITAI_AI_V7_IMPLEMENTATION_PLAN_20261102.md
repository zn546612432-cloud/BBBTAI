# 《熙蒙的手机》· 陈熙泰 v7 落地设计与开发路径

版本：2026-11-02。状态：**开始实施，前两项为纯函数基础模块；尚未接入游戏运行时及真实模型**。

## 0. 不可改动的底线

- 游戏仍由 GitHub Pages 静态发布：`https://zn546612432-cloud.github.io/BBBTAI/`；不迁移整个游戏至 Supabase。
- Supabase `ximeng-phone-ai` 仅负责熙泰的持久记忆、生活状态、行为日志、待执行动作及安全 AI 接口。DeepSeek 决定行为与台词，MiniMax 负责声音。
- **当前只有作者本人玩**：不开发注册页、公开用户运营、多人扩容。后端身份通道作为技术基础后续解决；不可将 service-role key 或 AI 密钥写进 Pages 客户端，也不能完全无鉴权开放 Edge Function。
- 55 天主线、D01 前历史微信与朋友圈、锁定剧情、D55 终局录音不可删改；第二视角不可被自由 AI 改写。
- 相认前的 MIRAGE 角色名、亲缘关系保密，按剧情实际 `recognition` 节点判断，不允许只根据 D30 日期判定。
- 固定 MiniMax 音色 ID 和 `emotion=calm,pitch=0,speed=1`；AI 心境不修改音色。
- 旧游戏存档不自动清空或全量覆盖；回滚开关、安全快照与单独预览必须存在。

## 2. 最终交互（事件源 + 有状态导演）

熙蒙真实发出消息、熙泰活动到期、双方正在通话、玩家点击拒接等 → 获取已发生可见事实、最新对话、人物生活状态和相关长期记忆 → 第一阶段 DeepSeek 只选择 `action/strategy/intent` → **程序校验** 时段、故事阶段、上一消息、权限、通话占用、冷却、TTS 能力 → 第二阶段 DeepSeek 产生纯台词 → 真实执行文本/语音/来电/已读/延时 → 落库执行结果 → 后置抽取新事实与记忆 → 更新长期关系、生活和待办事件。

行为策略不是软件副作用：「调戏、敷衍、反问、冷淡」属于 `strategy`；「发语音、打电话、已读、暂缓」才是 `action`。AI 说“现在打电话”绝不能替代真实 `startIncoming`。

## 3. 记忆系统细化

### 3.1 四层记忆（都只存可追溯事实）

- **即时工作记忆**：当前连续 2–5 条玩家消息、上一轮回复、通话上下文、未发送承诺。进入请求时实时构造。
- **情景记忆（episodic）**：D33 熙蒙谈电影、D34 发生争执、D35 和解等事件；注明日期、频道、来源消息 ID、事实可信度。
- **长期偏好/关系记忆（semantic）**：熙蒙喜欢杰克、熙泰在乎某个约定；区分明确陈述与推断，冲突时标记旧记忆被更新，而非直接抹掉聊天原文。
- **生活/承诺记忆（prospective）**：熙泰说过几点打来、决定去洗澡、订了什么活动；有到期时间、取消原因和实际完成结果，不用“提示词里说会做”冒充程序已完成。

### 3.2 提取机制

AI 后置抽取器每段实际对话结束后分析**新发生**的消息，输出 `fact_candidate`、`relationship_event`、`promise_event`，带证据 ID 与可信度；程序检查候选是否直接受原文支持。推断只能标为 hypothesis，不会擅自升级为事实。常规闲聊可以不提取任何记忆。每条新消息只处理一次。

保留作者手工世界书优先级；角色自述的生活安排可成为生活事实，但“模型替熙蒙虚构的回忆”不得进入人物关系记忆。记忆需要遗忘/归档/版本策略而非不断塞同义内容。

### 3.3 召回机制

每轮先根据话题、发生时间、重要性、频道访问权限筛选候选；第一阶段先用关键字/中文二元片段评分，避免立即引入 Embeddings 成本。后续再根据真实聊天效果选择是否增加 pgvector/语义向量。

每次只取少量高相关记忆，并明确告诉模型“来源/可信度/时间”；不能每轮粘贴数百条记忆引起噪音。已发生 MIRAGE 匿名信息不可在未相认期泄露；NoApp 个人私聊默认不回流到 MIRAGE。固定剧情未来资料绝不进入召回。

基础模块：`src/services/ai/v7/memory-selector.js`，当前是纯函数、没有替换现有 UI。

## 4. 人物关系及生活

- **关系**：保留长期亲密趋势，同时记录信任、恼怒、担忧、冲突、修复等独立事件；不因为出现“想你”就机械连加分。短期心情、人物底色和长期感情分别建模。
- **生活**：重要出差/剧情安排预设；自由时间由 AI 选择，状态字段 `where/activity/started_at/expected_end/contactability/commitment`，每次声明生活行为都必须提交事件，不能每轮重抽。
- **时区**：以澳门游戏日期为剧情权威，同时记录熙泰英国/巴黎当地钟；禁止由于玩家跳日、暂停或重新载入导致自动推演未发生剧情。
- **自主联系**：用户此前选择「游戏网页运行期间跨 App 来电消息」。任务调度由状态和事件触发，程序在页面运行时取任务并验证，已关闭网页的真实 iOS 后台通知暂不在本阶段实现。

## 5. 行为导演协议

第一阶段要求单一 JSON（不输出隐藏推理），字段：
`schema_version,source_message_id,action,strategy,intensity,intent,delay_seconds`。

`action`：`send_text/send_voice/start_call/read_no_reply/defer_reply/end_session`。
`strategy`：`answer_directly/tease/ask_back/brief_pushback/challenge/share_life/comfort/serious/deflect/set_boundary/repair_misunderstanding`。

校验内容：合法 JSON、来源消息 ID 未过期、剧情锁和相认状态、通话占线、玩家禁止来电、冷却、MiniMax 是否可用、已读是否真的产生。无法执行语音/电话时不能显示“已发/已拨”，应该由模型重新决策或使用可解释的文字降级，不能用承诺替代操作。

基础模块：`src/services/ai/v7/decision-contract.js`，无 side effects，运行时接入之前只作为验收门禁。

## 6. Supabase 与 GitHub Pages 的具体桥接

`Pages` 浏览器 → `Supabase Edge Function tai-brain`（只接收合法认证请求）→ 数据库 + DeepSeek + MiniMax。Pages 继续运行现有游戏前端，无须重建网站。

当前服务端 `tai-brain` v1 只有基础操作，所有 AI 动作仍未激活；后续才添加 persona/remember/direct/respond/commit/reconcile 端点。API 密钥需要配置为服务端 Secrets，**不提交 GitHub**。

这是作者单人游戏，暂时不做登录 UI，但服务端仍然必须具备最低限度认证；可以将设备静默身份认证/一次性配对作为开发集成步骤，不能把凭据写死到公开仓库。游戏已存档与测试存档必须分开，不允许因新后端 bootstrap 清空老故事。

### 6.1 消息与数据库一致性

客户端消息 ID → 事务性持久化 → 决策日志 → 带唯一 `idempotency_key` 的 pending action → 执行后的最终状态。多次点击、重试、iOS 网络断开不能发重复来电或语音。未接电话和用户主动拒接必须区分。正文可能多气泡，但在数据库是一轮确定过的行为。

未来补充“场景已相认”的更新 API，不能把 `bootstrap` 默认 D01/anonymous 的状态误用为后续 NoApp 已相认。剧情阶段以当前游戏存档经校验的实际完成事件为准。

## 7. 实际实施路径（每一个步骤有验收）

**V7-A：纯核心与测试（本分支已开始）**
1. 完成来源受控的长记忆检索函数及行为结构化协议。
2. 测试：未来记忆被拒、跨渠道信息不能泄露、关键词查回 D33 喜好、旧行为禁止重发电话、没有 MiniMax 不生成语音。
3. 对 `main` 零行为影响，可单独回滚。

**V7-B：记忆入库闭环**
1. 创建运行时适配层，不一次修改所有手机 App。先接 NoApp 的真实自由聊天；对话读取上下文时在本地/云端适配器抽取候选记忆。
2. 实现一次性事实抽取与 source message ID、可信度、消歧/版本更新；人工开发者面板可审阅记忆。
3. 验收：D33 在 NoApp 分享偏好，D40 主动提起相关话题时可以正确回忆；不是直接复制示例句。测试存档重启后仍在。匿名 MIRAGE 的 D10 任务不能泄露未发生的相认事实。

**V7-C：双阶段决策 + 语音/来电**
1. 替换 NoApp 中的关键词触发为行为导演。程序校验后，第二次生成真实台词。
2. 明确 `send_voice` 与 `start_call` 分开。试听和播放延用既有 MiniMax calm 固定音色。
3. 验收：主动要求语音 → 合法时出现真实可播放语音；要求电话 → 玩家接听才朗读；不愿打时拒绝，不“假装已经拨号”。异常时不黑屏不重复播放。

**V7-D：生活与主动事件闭环**
1. 生活状态事件化；互相约定有到期调度；已读/延迟/离线是真实状态。
2. 把现有 `proactive.js` 改成统一调度器，支持跨 App 主动联系；不重复/不因跳天补发。
3. 验收：熙泰先说去洗澡，下次仍记得自己在做什么；拒接后是否追问受关系和心情影响，不机械回复。

**V7-E：回归与上线**
1. 开发者模式可查看行为、执行记录、记忆候选与真实记忆、原因码。测试未知 JSON、反复点击、存档回滚、匿名阶段、两种时钟和关键音频。
2. 真实手机检查 iOS 点击播放/暂停、来电叠层、锁屏及后台限制。
3. 只有上述测试通过才合入 `main`，GitHub Actions 继续部署 Pages。

## 8. 真实人物质量测试（不提供固定台词）

- D33 对熙蒙提到的《圣诞惊魂夜》杰克建立真实事实，D40 适时相关回忆；不把相关作品编成虚假共同旅行。
- 刚刚说要洗澡；熙蒙要他马上打电话：可拒绝/延迟，状态一致，不失忆。
- 熙蒙连发两条再补充：聚合后按最后事实决策，不旧消息重复起动作。
- 无意义问候与长篇倾诉：一句简短和长篇表达都可，不强制 5 条，不机械提健身房。
- 熙蒙明确拒接：不能反复拨号；尚未接听的电话不播放第一句话。
- D10 MIRAGE：冷静带刺的衔尾蛇；不提前知道现实中不可能公开的亲缘。
- 重试同一消息：相同 source/action ID 只产生一次 side effect。
- D55 终局：固定台词、录音及 03:00 逻辑不受自由 AI 覆盖。

## 9. 当前完成与尚未完成的真实界限

**已完成：** GitHub main 整合 v6；Supabase 七表、RLS 和 `tai-brain` v1 已部署；v7 分支已加入纯函数记忆筛选、行为结构校验及测试。

**未完成：** 记忆抽取 AI、云端记忆真正写入 NoApp、第一/第二阶段接入 DeepSeek、端到端 MiniMax 语音与电话、活动日程管理、主动联系调度、用户实际完整测试。本文件不是“整个 AI 已上线”的声明。

后续实现不要问用户更多细枝末节；先跑通真实交互再根据失败案例修正。
