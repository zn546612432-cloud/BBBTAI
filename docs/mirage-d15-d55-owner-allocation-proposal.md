# MIRAGE｜D15–D55 82單 × 70位雇主分配提案（待審）

> **審核用途，不是已部署數據。** 基於 `main` 的 `src/story/d15-d55/commissions.js` 實際82份可接委託與15份不可接展示。這份提案只調整可接委託的 owner 歸屬，沒有修改遊戲程式、任務標題、S/A/B/C 等級、獎金、截止、關卡或觸發。

## 約束和驗證

- 41天（D15–D55），每日2單：**82單**，不補單不刪單。原始ID包含跳號（M-001、M-002、M-006…M-085），全部保留。
- **70位不同雇主** = 20位有個性雇主（維持原有 @handle）＋50位普通雇主（50個新 @handle），不是70個聊天劇情節點。
- 20位有個性雇主承接 **32單**；50位普通雇主各承接 **1單**；合計82單，因此存在 **12次同雇主再次合作**。
- 15份不可接懸賞（R系列）保持原樣，不算入可接雇主70人，不能因展示就生成聯繫人。
- 這是**訂單指派提案**：下表原雇主與拟定雇主分開列，需審核後再寫入。20位特色雇主的寫作性格也只是提案，不是假稱已定稿。

## 已確認的對話規則

- 每筆委託在 **OPEN → ACCEPTED** 真正成功後，於該雇主的既有或新會話內先出現：`── NEW CONTACT ──`，發送者為 `system`；**每筆订单仅一次**。
- 下一條是雇主接單私訊；**COMPLETED** 時雇主驗收私訊；**已接單後 EXPIRED** 時雇主失敗私訊。沒有接單時不新增聯繫人；Ghost 可重試的單關失敗不等於整單失敗。
- 同一雇主不同訂單沿用同一聯繫人與歷史窗口。KIRA 只管附件/密鑰/支付回執，不重複雇主對話。
- 50位普通雇主獨立暱稱、獨立聊天紀錄，但共用下述模板；20位特色雇主使用獨立、連續的人物台詞。

## 實施邊界／風險

1. 更改訂單 owner 可能影響存檔、委託快照、之前已出現的雇主與測試；必須先設計精確對照的遷移與保護，不能直接覆蓋玩家已接/已完成訂單。

3. 不可接 R 系列不改，原 Mirage 預設其他角色（如 Isolde、Rookery 等）保留原身份，不硬映射成委託雇主。
4. **不得因審批此表而自動合併棋局 PR #146 或直接修改 main。** 之後在獨立分支先寫測試，再最小修改資料及同一消息生命週期。
