# 小手机交接：以 FoundPhone 为参照继续修复

当前仓库是熙蒙小手机游戏。参考项目是 [FoundPhone-Studio](https://github.com/keoyyo85/FoundPhone-Studio)（MIT）；请先阅读它实际的 App、后台、手势、图标与样式实现，再逐屏对照本项目。当前提交是待验收的预览版，不能把已有页面视为完成。

## 用户明确要求

1. 每个软件一个子文件夹，每个功能再分子文件夹。沿用本项目数据和存档，保留设置中的开发人员入口。
2. 后台卡片必须适配模拟 iPhone 的尺寸：左右滑动切换已打开 App，点卡片返回，向上滑卡片关闭；App 从底部上滑缩小消失进入桌面/后台。触摸屏与鼠标都要实际验证。
3. 桌面提醒事项组件不得压住、露出或覆盖下面的图标；不同宽度和高度都检查。
4. 设置的每个可见入口都应有可进入的页面和明确返回路径；不要只有外观。音乐的所有可见按钮应可用，不能出现点了无反应的控件。邮件页面也需要对照参考改善。
5. 图标优先使用用户提供的图片，以及参考项目允许使用的原始资产。不要自行生成或画新的近似图标。澳觅采用用户的图标与页面素材；用户点“获取验证码”固定显示“请输入正确的手机号”，不能真的登录。
6. 主动逐屏比较参考项目与本项目的视觉、动效、触控和功能，自己记录发现的问题并修好，不要等用户逐项指出。

## 已知尚未达到的地方

- 设置中一些开关目前只模拟本游戏状态，没有真实系统效果；应梳理每个可见控件的合理游戏内行为。
- 音乐目前只有一首可播放的本机音轨，“下一首”只能重播同一首。不要展示无法兑现的曲库和播放操作。
- 邮件与部分 App 仍有文字符号充当图标；需要按用户提供的截图和参考项目核对。当前仓库不含全部聊天附件，缺的原图要明确列出，不要自行生成代替。
- 98 个现有测试通过、构建成功只能证明基本回归；后台触摸手势、尺寸适配、图标一致性、每个页面可进入都需要真实预览检查。

## 交付标准

- 在 393×852 模拟 iPhone 以及窄屏、较矮屏实测首页、提醒组件、后台的横滑与上滑、设置逐项导航、音乐全流程、邮件、澳觅；记录每项通过或失败。
- `npm test`、`npm run build` 通过。对实际发现的手势/路由风险补充有意义的测试。
- 给用户预览地址和简短的逐屏对照结果，列出未完成项。用户确认后再合并/发布后续修改。
