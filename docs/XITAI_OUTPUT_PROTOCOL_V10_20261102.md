# 《熙蒙的手机》｜陈熙泰输出与行为执行协议 v10

**这是动作协议，不是人设或对白世界书。** 输出格式必须优先于“活人感”修辞。状态：独立分支实现与测试；不自动覆盖 main 的固定剧情。

## 1. 为什么不能再只有“messages”
模型输出“我打给你了”“我不理你了”“先挂”并不会改变游戏状态。旧的 `(phone)` 只是 NoApp 的临时兼容入口，不能表达“已读不回”“暂缓回复”“主动挂电话”“发一条语音”“结束交流”，也无法准确执行有情绪的多条消息。

**新协议是两阶段：行为决策 → 程序验证 → 语言生成 → 程序执行。** DeepSeek 可以选择，不能自行宣布真实副作用发生；熙蒙固定剧情和当前游戏状态永远优先。

## 2. 第一阶段：只选行为，不写台词

```json
{
  "schema_version": 10,
  "source_message_id": "真实消息ID；自主联系可为空",
  "action": "send_text",
  "strategy": "tease",
  "intensity": "low",
  "tone": "playful",
  "vocal_cue": "none",
  "intent": "简短的内容方向；不是人物台词或长篇思考",
  "delay_seconds": 0
}
```

**聊天动作只有以下六种：**

| action | 意义 | 必须由程序完成 |
| --- | --- | --- |
| `send_text` | 发一条或多条文字 | 实际生成与投递气泡 |
| `send_voice` | NoApp 发语音条 | MiniMax 成功后才有可播放音频；不可当成电话 |
| `start_call` | 熙泰主动发起 NoApp 电话，或响应熙蒙的请求 | 真正响铃、接听/拒绝、未接记录；接听前不发音 |
| `read_no_reply` | **已经看到熙蒙消息，但选择不回复** | 标记源消息已读时间，不产生回复气泡；不能伪造已读 |
| `defer_reply` | **还未处理消息，决定晚些回复** | 记录延迟与到期时间，调度器必须再验证；不能显示已读 |
| `end_session` | 暂时结束文字交流 | 允许短暂告别或结束，不等于网络离线、注销或封锁熙蒙 |

**正在通话时，另有三个专用动作：** `speak`（回应）、`hang_up`（由熙泰真正挂断，可以先说一句）、`listen`（保持安静、等待熙蒙说话）。`hang_up` 不是文字说“挂了”，而是音频播放完毕后真正改变通话状态、记录通话。若被熙蒙抢先挂断，AI的旧决定失效。

## 3. 表达策略与情绪是独立字段

`strategy` 只描述如何说话：`answer_directly`、`tease`、`ask_back`、`brief_pushback`、`challenge`、`comfort`、`serious`、`deflect`、`set_boundary`、`repair_misunderstanding`。

`tone` 记录当前情绪：`neutral`、`dry`、`playful`、`soft`、`serious`、`danger`、`happy`、`sad`、`angry`、`fearful`、`surprised`、`disgusted`。`intensity` 是 `low`／`medium`／`high`。

可选的 `vocal_cue`（`none`、`small_laugh`、`sigh`、`hesitate`、`tired`、`whisper`）是元数据，**不在文本中显示、也不送入 MiniMax 朗读**。声音仍维持唯一指定音色、`emotion=calm`、`pitch=0`、`speed=1`；不能靠模型自行改变声线。语音层以后可以在音色稳定的条件下有选择地实现细节；不把心情简单等同于 TTS 音色变化。

熙泰可能因为被熙蒙打断而恼怒、因为哥哥的代码而惊讶、因为一次误会而沉默；情绪必须来自当下的真实信息，**不能每次随机抽一个情绪标签**。

## 4. 第二阶段：按批准动作输出内容

需要台词时才调用第二阶段。文本/语音内容仅返回 JSON `messages`，每条 `{ "text": "...", "mode": "text|voice", "tone": "dry", "vocal_cue": "none" }`，可选 `translation`；多条消息属于同一动作，不能夹杂第二种隐式动作。不允许输出 `(phone)`、`(voice)`、`(read)`、`(offline)` 等作为新系统的动作控制；过渡期旧存档兼容单独处理。

对 `read_no_reply` 和 `defer_reply` **根本不调用第二阶段**：否则模型会被迫写台词，破坏沉默的真实性。`start_call` 先执行响铃，接听后才允许生成可听见的开场。`hang_up` 可以先生成一句口头告别，播放结束后程序挂断。

## 5. 执行资格与强制闸门

- 只有 NoApp 相认后才允许语音条、来电与自由电话；匿名 MIRAGE 的 AI 开关默认关闭。
- 检查真实当前消息 ID、游戏日、关机/死亡/剧情锁、是否在线、玩家是否明确说“别打”、是否已在通话、MiniMax 是否可用、是否已执行过该动作。
- 新消息到来、跳日、关机、拒接、取消或页面关掉后，陈旧的动作不得继续执行。没有真实 read receipt 时间绝不显示“已读”。
- `defer_reply` 最多同一来源延期一次；到期后再次检查是否已回复、是否进入固定剧情或玩家刚说不用回复。离线时不能假装继续在后台运行。
- 熙泰可以真正主动打来，也可能不愿接听或突然挂断；但“会这样”不等于“每次都这样”，需要实际情境与状态支持。
- 有明确电话请求时，模型可选择接听或拒绝，**不能仅发“我现在打”就算完成**。

## 6. 人物的自主性不能变成话题轮盘

他有自己的作息、研究、健身与社交，但不会主动报备自己在干什么。更好奇熙蒙本人说过的事情；不能每次问“你在干什么”。

**国际象棋只随固定剧情触发。** 即使记忆中存在某盘棋，也不得将其视为长期关注话题、自动主动邀棋或催问棋局。动态动作层不得擅自触发、重启或重复任何剧情棋局。

## 7. 验收

程序测试至少覆盖：有效和无效 JSON、未知动作、陈旧消息 ID、重复来电、玩家明确拒绝、匿名期权限、缺少 MiniMax 时降级、读后无气泡、延期未显示已读、到期只重试一次、熙泰主动挂断但不会在音频未放完前中断、电话期间收到新用户输入使旧动作失效、情绪标签不被朗读、固定剧情不被覆盖。真机测试还要检验 iOS 接听手势限制和真实 DeepSeek/MiniMax 的跨多轮稳定性。

## 8. 实现边界

这套协议的 **字段、校验、文字/电话调用、已读状态** 与真实连接情况，以该分支测试代码和 CI 结果为准；尚不能把“写出规则”误称为“服务器持续在线、自主后台调度和 Supabase 记忆都完成”。GitHub Pages 是静态页面，浏览器关闭时不会替角色后台自主拨号。
